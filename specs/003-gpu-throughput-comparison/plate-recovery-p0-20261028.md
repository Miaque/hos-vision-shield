## 根因与安全职责

`quality.Detector.detect_regions(kind=None)` 将未获最终确认的主模型车牌候选汇总为
`has_unconfirmed_plates`。原 `FrameRedactor.regions` 在任何该候选存在时，禁止所有新鲜车牌的
失败光流转模板恢复，进而沿共享 `recheck` 升级完整检测。

该标志保护的不仅是错误关联，也包括新弱候选短暂的全图主模型确认机会。
源码已有第二段第 939 帧的反例：未来窗口从未确认目标时，前视不能修复早先遗漏。
因此仅按候选远离失败轨迹就放行并不安全。此初步方案在本轮合成复现中有六项明确丢失必要复检，
已在实验提交前弃用，没有将它作为可用候选。

## A1 最小范围

- 全图质量检测同时保留 `unconfirmed_plate_boxes`，原布尔由其派生；人脸及局部车牌调用不覆盖快照。
- 先计算全部原始光流结果，再逐轨迹判断模板准入，避免轨迹遍历顺序决定结果。
- 保留 bounded lookahead 开关、车牌类别和 `seen <= 0.2s` 的原准入。
- 有未确认候选时，完整快照必须新鲜（距最近成功完整检测不超过 0.2s）。缺失或过期仍阻断。
- 候选落在失败轨迹原模板搜索范围（四边 96px）内，仍阻断，防止竞争关联。
- 范围外候选也不能直接忽略。每个候选须关联到另一条 `seen <= 0.2s`、当前原始光流成功的车牌轨迹，
  与旧框 IoU 至少 0.2，且当前光流框覆盖候选至少 90%；否则保留原全图保护。
- 以上两个覆盖/关联门槛复用既有轨迹关联及新目标提案覆盖语义，没有放宽模型确认门槛。
- 继续调用原双向 `_follow`，其有效性、相关分数、反向检查、拒绝后的完整检测均保留。

几何关联仍不能证明目标身份或字符真值，解除次数不能直接称为有效恢复。只有完整质量复核后才可计入有效收益。
本轮没有修改 LK、最低六点条件、模型、前视补遮/缓存/等待策略、周期检测或新目标提案路径。

## 计数口径

新增计数仅在 debug 时累计：

| 字段 | 含义 |
| --- | --- |
| template_eligible | 原始光流失败、满足原车牌/新鲜度/前视条件的事件 |
| template_global_blocked | 上述事件中原全局布尔会阻断的次数 |
| template_blocked | A1 关联门控实际阻断次数 |
| template_attempts | 实际调用原双向模板次数 |
| template_rejections | 原模板返回 None 的次数；模型异常仍向上传播并终止，不静默输出 |
| template_fallbacks | 模板返回位置次数，尚非人工验证的有效恢复 |

`template_global_blocked - template_blocked` 是实际解除事件数，不能等同完整检测帧或模型调用节省。
保持 `eligible = blocked + attempts` 和 `attempts = rejections + fallbacks`。

## P1 调用链核对（未改实现）

原始 `_flow` 返回 None → 共享 `recheck=True` → `face_only=False`、`detect=True` →
`_detections` 调用完整 `quality.detect_regions`，主/补模型及局部确认按原门槛运行。
该帧其他成功光流也进入完整检测后的跟随逻辑，存在单目标失败的检测放大。

正常 CUDA 跳帧并非零推理：`plate_proposals` 已运行主人脸及全部 detail 候选，
`detect_faces` 消费同一帧缓存；若提案要求完整复核，`detect_regions` 复用缓存后追加主车牌。
故不能把每次完整复检乘以四个模型。尾部 discover 和反向补遮的局部确认也要计入净成本。

按类别补检仍需要保留独立的人脸/车牌全图发现；目标 ROI 无法发现其他位置的新目标。
P1 必须在 P0 质量与 RTX 验证后独立实验，不能以减少分支次数替代实际 forward 和双路吞吐验收。
