## 代码差异与实时验收缺口

`git diff 581c175 ab676bf` 显示候选同时包含公共推流、诊断和部署能力，不能将全部差异视为合批。
质量确认 `detection/quality.py`、调度和光流 `redaction.py`、主模型 `detection/yolo.py`
及 `detection/egoblur.py` 与固定对照无差异。合批实现位于 `detection/cuda_detail.py`，
同帧视图每批最多四张；不改变原始视图枚举和质量确认规则。

`media/streams.py` 尚不能承载本任务正式实时验收：

- `StreamBuffer.frame` 满队列丢旧帧；`take` 取最新帧并清空积压帧，与本轮不主动丢帧要求不符。
- `process_stream` 通过普通 `av.open` 解码，`masked_frame` 转为 CPU RGB，
  `add_video` 未传入 CUDA 设备；不能用离线 NVDEC/NVENC 路径证明实时 GPU 路径已完成。
- 实时 `FrameRedactor` 未传入离线 interval/flow 参数；不能把离线调度收益外推到实时。
- 当前计数发生在提交编码帧之后，最终输出计数、保护帧和延迟分位数仍需独立实现和核验。

上述为源码证据，未在本轮改动实时实现；先完成合批离线收益判断，再进入实时阶段。
