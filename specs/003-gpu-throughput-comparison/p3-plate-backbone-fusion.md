# Ada 主车牌骨干融合实验（2026-10-25）

本实验以内部异步迁移与 attempt 诊断、停流顺序修复为基础，保持两路流、两个 GPU 文件并发。
已撤回无稳定整体收益的单图 ROI 格式改写；原 ROI 格式、RPN、候选数量、NMS、四层 ROIAlign
与后续检测规则均保留。固定算法对照 `581c175a` 不变，本项的直接执行对照为
`0bcddc7` / `exp-20261025-a-single-image-pooler-control-01` 的运行代码。

## 新的验证条件与实现

历史骨干冻结只在 GTX 1080 上测试，完整前向仅改善约 0.37%，未采用。
当前 RTX 6000 Ada trace 中仍有 112 个 BatchNorm，卷积与小算子发射的成本比例已不同，
本轮以减少 Ada 上归一化执行及发射成本为新假设，不原样宣称旧实验已有收益。

只冻结主车牌骨干，然后将其内联进复制的原包装图。原模型图不被修改；保持 FP32 归一化缓冲区、
原半精度执行契约及 CPU 尺寸元数据，并沿用 17 个内部设备迁移的异步标志。
包装层结构不符、归一化未折叠或设备迁移节点不符时失败关闭，不静默切换执行路径。

[PyTorch freeze 说明](https://docs.pytorch.org/docs/2.9/generated/torch.jit.freeze.html)明确指出，
数值优化并不保证逐位一致。权重文件与精度配置虽未改变，融合仍会折叠参数并改变运算顺序，
因此必须独立校准半精度框、分数、最终遮罩及媒体输出，不能只检查算子数量减少。

## 本地验证与服务器门槛

回归先在未融合图上复现失败，再验证空输入、单元素和 17 个元素的完整输出，
原图与输入不被修改、原 CPU 下载仍阻塞、原内部迁移仍异步，以及归一化被消除。
设备迁移与调用方定向检查 18 项通过；完整 unit 集合 585 项通过、48 项按既定 GPU 条件跳过。

产品图 CPU 检查覆盖 32×32、319×321 空图及 360×1280 七车牌输入：
112 个 BatchNorm 归零，四个 ROIAlign、原 repeat_interleave 与 17 个迁移均保留；
空图输出逐位一致，七车牌的坐标与分数最大差约 0.000031 像素、0.00000122，类别和尺寸相同。
原型、产品图和检查结果保存在 `route-a-backbone-fusion-ada-20261025-01/`。
本地没有 CUDA；上述 FP32 CPU 结果不证明服务器半精度质量、性能或初始化成本。

服务器先使用现有固定区域 PNG 质量检查及独立双流双文件 CUDA 采样，核对真实算子、
完整输出、NVDEC/NVENC、实际重叠、attempt 结束记录与初始化时间；带 profiler 的耗时不用于收益判定。
通过相应校准后，才进入不带 profiler 的三组完整混合负载比较。未通过前保持实验候选身份；
质量、逐路实时门槛及 30 分钟连续播放均不能由模型内或 CPU 微基准替代。

服务器已部署 `7dc3e18` / `exp-20261025-a-backbone-fusion-01`。
固定区域 PNG 检查为 8 项通过、7 份源缺失，rtsp-green 仍未满足其既定必遮区域；
九张实际输出均与内部异步迁移版本逐字节一致，包括该已知失败案例。
这只证明可用图片未新增输出变化，不是绝对质量通过。

## CUDA 采样与待处理的整片差异

两流与两个 GPU 文件的独立采样已完成。两份均为 1776 帧、零丢帧，NVDEC/NVENC；
六份原始 trace 没有 BatchNorm 事件，运行源 SHA256 与 `7dc3e18` 对应，参数为 CUDA FP16，
主人脸及补检测仍为 CUDA provider。两条流主动停止原因均已持久化，任务与队列已收尾为空。

两份媒体耗时 107.387/107.474 秒、模型加载 10.322/27.105 秒。本轮有 profiler，且上传先后
导致两文件开始时间不同，因此不能与普通三组对照直接推导收益。
调用序号 64/424/768 的同步次数仍为 15/17/17；调用分支变化后相同序号也不一定对应相同源帧，
不直接用这些采样差值宣称主模型提速。

两份完整输出确定性一致，SHA256 为
`dd2ded02a44e4b26721f3ef714bf2421ea395a008abad44fddbb86b34ebca081`，
但与原输出不同；已复核完整帧时钟、尺寸及 943 个 AAC 包内容与时钟。
检测/跟踪分支也发生小幅变化，例如 full_frames 870→866、flow_updates 563→571、
flow_failures 244→241。未修改检测规则，但融合浮点变化已传播到业务分支，不能宣称计算工作量不变。

整片校准当前明确未通过，`candidate-device/verification.json` 保留
`quality_review_required=true`、`candidate_accepted=false`；不把文件成功或九张图片一致视为足够证明。
逐帧灰色差分的初版在背景纹理上也受 NVENC 压缩影响，其计数不能作为漏遮率或质量标签。
原始差分记录保留，正在进一步定位强遮罩核心变化及实际目标；普通混合收益试验尚未启动。
