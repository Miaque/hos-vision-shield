# P2 小车牌跟踪与检测成本可行性分析（2026-10-28）

结论：**继续 P2；目前证据不足以证明某项新跟踪方式能安全降低净推理成本，先做最小旁路实验 P2-D0b。**
优先验证“从现有车牌框提点，替代当前内缩框提点”，保留六点及全部运动校验。
它有明确的角点供给改善信号，但尚无 LK 有效内点、目标身份、整帧复检消除和实际净 forward 收益的完整证据。
不因 P1 无可复现吞吐收益而停止分析，也不将增加角点或模板返回位置当作已实现收益。

## 1. 现有实现已经做了什么

源码位置：[redaction.py](../../src/vision_shield/redaction.py)、[quality.py](../../src/vision_shield/detection/quality.py)、
[plate_lookahead.py](../../src/vision_shield/media/plate_lookahead.py)。

`_flow` 每次调用都会在参考灰度图上重新执行 `goodFeaturesToTrack`，没有持久化跨帧特征点列表。
提点区域为遮罩框四边各内缩约 20% 后的内部区域；上限 48 点，qualityLevel=0.01、minDistance=3、blockSize=3。
内部区域短边小于 5，或初选角点少于 6，立即返回，尚未执行 LK。
LK 已使用四边 96px 的上下文视图、21×21 窗口、maxLevel=3；**扩大 LK 搜索视图不会自动扩大提点区域**。
之后还要求双向有效点至少 6、有效率至少 65%、回返误差不超过 1.5px、分布跨度至少框尺寸的 15%、
RANSAC 内点率至少 70%，并限制缩放和转角。

因此：

- “失败后重新提点”已经存在；重复添加初始化/重建并非新能力。
- 没有按具体车牌尺寸显式选择某种专用跟踪器；已有按区域可用性和角点数量退出 LK 的准入。
- `3/flow` 已对新鲜车牌执行 LK→模板回退，没有必要再增加一条等价的“小目标模板路径”。
- 可读性判断 `plate_needs_work` 服务于模型确认/提案，不是车牌尺寸跟踪调度器。
- 没有车辆检测结果或车辆轨迹可直接复用；已有类别仅为人脸、车牌。

## 3. 模板恢复：调用范围、成功率、拒绝与成本

新鲜车牌回退要求前视补遮已启用、原始 LK 失败、距真实确认不超过 0.2s，并通过 P0 的目标级门控。
若有待确认车牌，仍检查全图快照新鲜度、搜索区竞争，以及其他 fresh 原始光流轨迹的关联和覆盖。
新弱目标的确认机会、未知/过期状态、竞争关联不能因换一种跟踪方式而被绕开。

`_follow` 本身取内缩后的灰度模板，要求短边至少 3、标准差至少 2；在四边 96px 范围做正向相关，分数至少 0.8，
再反向匹配要求分数至少 0.8，回到原位置的误差每轴不超过 2px。它主要跟随平移；不等价于已验证缩放/旋转。
模板匹配本身不续期真实检测时间。

同一 `_follow` 还用于陈旧光流的定位检查、完整检测后未匹配旧轨迹的跟随，以及既有前视反向补遮。
故全部 `track-update` 调用远多于“新鲜车牌 fallback”次数，不能混为同一统计。

| 既有 RTX P0 fallback 指标 | A | B |
| --- | ---: | ---: |
| 符合原准入事件 | 1988 | 3689 |
| 实际门控阻断 | 1350 | 2598 |
| 实际模板尝试 | 638 | 1091 |
| 返回位置 / 拒绝 | 606/32 | 1036/55 |
| 获准尝试的返回位置率 | 94.98% | 94.96% |

高返回率不是身份/字符真值成功率。它说明“再加相同模板”可扩展的直接机会很少，大量未尝试事件另有安全原因。

本轮原模板旁路中，可定位为原来实际获准尝试且参考图可确定的拒绝样本为 A21/B38：
A 正向分数不足 10、反向位移不符 11；B 分别 10、28；该子集没有观察到反向分数不足或低纹理提前退出。
其余拒绝的完整原因未掌握，不能外推这些比例到全部 RTX 事件。
本地旁路对全部可确定参考事件运行原模板时返回位置 A998/B1615；其中大量原本被门控阻断，
这些数字仅用于解释潜在误关联，**不算有效恢复，不是建议放行门控**。

既有 RTX host 观察器的全部 `_follow` 所在 `track-update`：

| 项目 | A | B |
| --- | ---: | ---: |
| discovery 上下文调用 / 累计 host 秒数 | 2517 / 3.558 | 5628 / 9.660 |
| 其他 pipeline 上下文调用 / 累计 host 秒数 | 103 / 0.158 | 153 / 0.203 |
| discovery 单次 p50 / p95 ms | 1.137 / 2.644 | 1.574 / 3.127 |
| 全部 `_flow` 调用 / 累计 host 秒数 | 2975 / 0.929 | 5685 / 2.000 |

这不是 fallback 专属耗时，也不是正常 FPS 或 GPU 内核总时长；不能将并行/嵌套区间直接相加。
本地原模板旁路 p50 约 1.38/1.39ms，同样不作 RTX 正式性能比较。
计算上模板明显值得保留，但它已大量使用，不能假设再增加模板尝试就会节省完整检测。

跟踪失败列由 `full_rechecks` 减提案及固定输入场景重置数得出；后者沿用已验证 A0 口径。
没有把所有 `full_rechecks` 都误算成跟踪失败。
现有 RTX API 缺少逐失败轨迹到 forward 的完整关联；下述逐帧关联使用同源 P0 的本地诊断，数值不冒充 RTX。

本地 A550/B905 个非重置跟踪复检帧中，A439（79.82%）/B744（82.21%）有至少两条轨迹失败。
单失败仅 A111/B161 帧；它们也未必全部满足安全恢复条件。
主要调度问题是“同帧仍有未解决目标”，而不是某个单独事件能否让 LK 执行。

| 本地跟踪失败复检帧关联的模型调用 | A 整帧/ROI | B 整帧/ROI |
| --- | ---: | ---: |
| 主人脸 | 550/4 | 905/8 |
| 主车牌 | 550/638 | 905/958 |
| 补人脸 | 550/0 | 905/11 |
| 补车牌 | 550/1123 | 905/1807 |

这些是关联成本，**不是全部可消除的净成本**。正常跳帧已有主人脸及 detail 全图提案；
把跟踪失败帧改为正常跳帧，不能免掉这些模型。现有候选复用也必须保留。
最直接的毛机会是整帧主车牌及一部分车牌 ROI 确认；替代后的新 ROI、其他目标复核、提案升级和前视尾部都要扣回。
本地这类帧的主/补车牌 host 累计为 A96.467/16.319 秒、B157.851/27.355 秒，包含诊断开销和嵌套范围，不能当作净可省秒数。

若冻结既有轨迹并假设所有跟踪复检均安全取消、没有替代成本或额外发现，RTX 整帧主车牌毛机会为 A547/B898 次，
分别相当于四模型总调用量的 4.82%/6.68%；不是净节省预测，也不是耗时比例或完整流水线收益上界。
周期、新提案和场景异常保护均不在可取消预算内。

P1 的已验证教训是整帧分支减少不等于四模型一起减少：最终 A/B 各少 42 个完整帧，净 forward 仅少 102/164（0.90%/1.22%），
正常双文件重复没有证明可复现 FPS 增益。P2 必须继续测净成本，而非因此停止所有方向。

## 5. 候选比较

下表“机会”均以现有证据为限；没有把计数乘单次模型耗时当作 FPS 收益。

| 候选 | 潜在空间及当前证据 | 主要质量风险 | 实现/验证成本 | 顺序 |
| --- | --- | --- | --- | --- |
| 再加角点初始化/重建 | 每次已重建，没有新增能力；缓存只能省部分 CPU，不直接省模型 | 旧点漂移、错误续期 | 实现低至中，验收中 | 不重复做 |
| 完整车牌框提点，保留六点和全部运动校验 | 已知不足点样本中 A963/B1407 能达到六点；尚无有效运动和帧级收益 | padding 内的背景/邻车点、弱新目标确认机会被跳过 | 单点实现低，关联及全片验证中 | 首选旁路验证 |
| 1.5 倍上下文/车辆整体运动 | 角点供给更高，但无现成车辆轨迹；不能假定同一刚体 | 邻车、车轮、遮挡、静止背景、不同深度运动 | 中至高 | 完整框不够且证据支持时再考虑 |
| 小牌直接模板或简单按尺寸分流 | LK 拒绝后已有模板；已获准尝试返回率约 95% | 绕过门控、错配背景、丢新目标确认 | 实现低，安全验证高 | 不增加等价路径 |
| 模板多尺度/旋转/模板库 | 固定既有状态下，获准模板拒绝仅 RTX A32/B55 个事件；尚无其尺度变化占比 | 搜索自由度增加，重复纹理更易误关联 | 中 | 先确认真实拒绝原因 |
| 同帧同参考/同框模板结果复用 | 可能减少 fallback 后完整复检中的重复 CPU；现日志缺参数，未证明重复数量 | 缓存键缺 reference/时钟导致复用错误 | 实现低，验证低至中 | 次要，先数清重复及瓶颈 |
| 增加车辆检测模型 | 尚无证据额外模型成本可由少量恢复抵消 | 车辆与车牌关联错配 | 高 | 本轮不引入 |

若完整框 LK 仅用于现有门控允许且模板已拒绝的事件，固定状态的直接机会池至多是上述 A32/B55 个事件，
还须扣除同帧其他失败，实际可能为零；不是重跑后轨迹历史变化的严格上界。
本地可确定参考的这类失败中，完整框能达到六点仅 A17/B33 个事件，仍不代表 LK 成功。
多数可供点样本原先处于全部门控阻断帧；不能把改良 LK 当作绕开 P0 安全职责的办法。
详见 `corner-vs-frame-gating.json`：全部阻断帧中的已知参考事件 A684/B1153，全部尝试帧中为 A351/B531。

## 6. 最小补充实验 P2-D0b：旁路验证完整框提点

本轮 D0a 的只读尺寸/角点分析已完成。**D0b 尚未实施，不直接创建改变输出的 P2 优化版本。**

唯一首选变量为“内缩提点框→完整原车牌框”；不放大到车辆区域，不降低六点门槛，不改变 LK、模板、模型质量或寿命门槛。
在独立分析/实验分支运行旁路，不修改生产函数、轨迹状态、缓存等待策略或服务器。

最小样本已定位到 A28/B20 个帧：所有参与跟踪车牌的参考均可确定，所有已记录原始失败目标在完整框提点能达到六点，
且这些帧原本确实发生跟踪复检；包含单失败和多失败，见 `d0-sampling-candidates.json`。
这 48 帧只是定向试验样本，不是可省帧数，也不是全部素材机会的上界。

执行与记录：

1. 在这 48 帧及对应真实参考帧上，冻结 P0 轨迹和检测结果；并加入原 LK 成功、中大车牌、重复纹理、相邻车、模板反向拒绝、画缘及新弱候选对照。
2. 只旁路比较原提点与完整框提点，记录初选点、双向有效点、RANSAC 内点、分布、变换和计算时间；全部原校验不变。
3. 逐目标检查预测是否仍为同一车牌、是否覆盖可读字符；“检测到另一块真车牌”不能替原轨迹续命。
4. 对每帧列出全部未恢复目标、P0 待确认候选/门控原因、新目标提案，以及必要完整检测是否仍需保留。
   不能因为新 LK 返回位置，就跳过原本用于弱新目标确认的主模型机会。
5. 对“身份与覆盖通过、同帧所有失败均解决、必要发现仍保留”的样本，列出实际可替代的模型操作和新增操作。
   冻结调度下的估算仍标为估算；实际 forward 净值须在后续改变输出的完整回放中测量。

进入后续独立 P2 实现实验的条件：存在一批可定位、质量通过、现有模板未解决且有净模型成本空间的帧；
收益不是主要来自绕过门控、删首次发现或改变短暂漏遮容忍标准。
若仅增加点数、只救回已有模板本就能恢复的目标、或同帧仍需完整检测，暂停此 ROI 候选并保留记录，不能宣称 P2 成功。

条件满足后才进入 P2-A：独立中文提交、相关单测、短片、完整 A/B；
统一模型/精度/配置测各模型实际 forward 及输入区域、正常与额外成本、资源和媒体耗时；
再在另行授权的 RTX 实验窗口对照单路、双路及真实流端到端 FPS，详细 host 诊断与正式性能运行分离。
质量覆盖字符漏遮、误遮、身份、闪烁、拖尾、新目标初始化及既有前视补遮，不引入 NvDCF 或车辆检测模型。

本轮未运行新的 LK 候选、未取得新遮罩质量结论、未测新模型净调用或新双路 FPS。
现有数据仍不足以承诺稳定每路 15 FPS 或向 30 FPS 的具体收益；这界定了下一项最小实验，而不是终止优化目标。
