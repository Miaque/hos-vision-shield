## 原路径与两个候选

原路径先读取五次 Tensor 布尔结果做数值校验，再执行 NMS、GPU 阈值筛选、分别下载
框与分数。标量读取会等待设备结果，参考 [PyTorch CUDA 说明](https://docs.pytorch.org/docs/2.14/notes/cuda.html)。

第一个候选在设备端合并布尔条件，只读取一次结果。合成 CUDA 候选调用范围内，标量
读取由 5 降为 1，runtime 同步由 11 降为 7，但三段充分预热后的处理耗时变化为车牌
-0.57%、人脸 -1.32%、夜间 0.80% 减少，未超过波动，不保留该实现。

第二个候选一次下载现有 FP32 框与分数组成的小表，在主机做相同数值校验，并在原 GPU
NMS 返回索引后复用此表筛选、还原坐标；NMS 仍使用原始 CUDA 框、分数和 0.3 阈值。
非法数值仍在进入 NMS 前失败，不允许发布部分结果；空输出和 float32 阈值边界保持。
只传输预测表和 NMS 索引，不下载完整视频像素。相比原路径，可能增加下载的预测条目，
以减少多次小操作和等待；该取舍需由整体测量决定。

本地 GTX 合成调用内标量读取为零、runtime 同步 11→5；原始 trace 含 CUDA NMS 和
keep-index gather 内核。该计时范围包含候选调用的预处理、NMS 和搬运，不能命名为纯
校验 GPU 时间，也不是模型前向耗时。2/128/1024 个预测的交错中位范围如下：

| 输入预测数 | 原路径 ms | 预测表复用 ms |
| --- | ---: | ---: |
| 2 | 1.308–1.316 | 0.661–0.716 |
| 128 | 1.531–1.538 | 0.769–0.822 |
| 1024 | 1.779–1.805 | 0.954–0.971 |

## 本地质量与总耗时

分别对两候选执行原路径/候选/候选/原路径，每种方案包含车牌 45、人脸 45、夜间 12
帧，共 816 次测量帧处理；另有预热。对应遮罩像素哈希、检测和跟踪计数全部一致。
第二个候选的平均处理耗时减少为车牌 -0.63%、人脸 -0.53%、夜间 1.75%，仍不能证明
本机整体稳定收益，更不能外推 RTX 性能。夜间已有漏遮仍未解决。

测试先复现原路径五次标量读取，再覆盖零次读取、空结果、NaN/无穷值、负分数、非法
宽度在 NMS 前拒绝，以及 float32 阈值边界和排序。最终默认 unit 集合 573 通过、48 条件
跳过；显式启用真实 GPU 的四个 `quality_yolo` 图片回归通过，包含既定遮挡/保留区域和
实际 ORT CUDA 节点检查。没有宣称全量集成套件或绝对质量通过。

原始报告、CUDA trace 与运行脚本保留在
`data/validation/route-a-primary-validation-20261024-01/02` 及同名前缀 `.py`。

## RTX 原路径/候选/返回原路径实测

目标设备确认为同一 RTX 6000 Ada UUID，按原授权命令依次部署 `3ee28e6`、

差值直接当作总处理节省。创建至完成的候选记录略短，返回对照仅相差 1–2 个整秒；
