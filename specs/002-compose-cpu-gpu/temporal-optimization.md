# 视频时序遮挡与按类别补检

2026-10-21。目标仍为 RTX 6000 至少两路、每路15–30 FPS；本次完成第一阶段改动，不代表整体性能目标达成。

## 改动

三个检测后端增加内部 `detect_regions` 接口，在扩框后保留类别和置信度；原 `detect` 仍返回相同格式的坐标列表。图片处理契约不变。视频文件和实时流共用的 FrameRedactor 按类别、一对一关联历史与当帧检测，防止车牌给人脸续期，以及同一检测重复取消相邻目标的遮挡。

连续检测采用保守边缘平滑：向外扩张立即覆盖当前框，向内收缩按源时间间隔渐进；单侧额外余量最多为当前框对应边长的25%。时间常数0.1秒是本轮合成序列和短片验证的初始值，并非所有场景的最终校准。平滑后的框包含当帧可信检测框，不用滞后位置替换当前检测。历史仍有128条上限；没有真实检测续期时仍受原有0.2/0.5秒寿命约束，转场/尺寸/时钟重置保持原规则。

局部补检按历史类别请求模型：人脸补检不再运行车牌推理，车牌补检不再运行人脸推理；全帧仍检测两类。任何实际执行的模型或局部补检异常仍向上传播，不能返回部分成功画面。没有新增依赖、模型、对外配置或API字段。

## 验证

- 新增时序回归先在旧实现复现框突然收缩和边缘抖动；后续测试另外复现了同一检测抑制两个重叠目标以及非法类别未拒绝。均已修复。
- `python -m pytest tests/unit tests/integration/test_video_pipeline.py -q`：209项通过，涵盖移动覆盖、有限拖尾、过期、类别隔离、局部失败传播、音轨和时间戳机制。
- GTX1080真实模型核对15个可用固定质量样例，标注遮挡/保留区域通过。`rtsp-green`截图缺失，未计为通过。
- 原视频1的1.8–2.5秒、视频2的9.8–10.5秒各15帧进入共用FrameRedactor；核对2秒小脸、10秒侧脸遮挡以及10秒手提包原像素。此为连续解码/遮挡验证，不是完整MP4编码、RTSP或逐帧人工质量认证。
- 同一局部裁剪交错运行全类别和仅人脸检测，排除首轮，后三轮中位耗时约267→201ms，减少约25%；人脸框和分数完全相同。仅为一个裁剪的局部补检收益，不是全片提速比例。

本地证据位于 `data/validation/optimization-20261021/`：源码基线、分段profile、`verify.py`、`quality-validation.json`、`recheck_benchmark.py`、`class-recheck-benchmark.json`。素材未上传。

## 尚未完成

当前每帧多模型与分块主路径仍在，不能达到或承诺两路15–30 FPS。之前CenterFace直接替换在困难侧脸上退化，未切换默认模型。后续需要比较轻量主检测和独立困难目标发现路径，并在实际RTX6000上验证两路吞吐、延迟、丢帧和画质。旧quality仍是质量对照。

本次平滑会增加有限的周边遮挡；若原检测是误检，平滑不能识别它的语义错误。多人交叉仍可能存在关联错误，未实现完整运动预测或身份跟踪，也未宣称全片误打码、漏遮或闪烁归零。尚未部署、未推送。
