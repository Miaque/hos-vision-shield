# 视频时序遮挡与按类别补检

2026-10-21。目标仍为 RTX 6000 至少两路、每路15–30 FPS；本次完成第一阶段改动，不代表整体性能目标达成。

## 改动

三个检测后端增加内部 `detect_regions` 接口，在扩框后保留类别和置信度；原 `detect` 仍返回相同格式的坐标列表。图片处理契约不变。视频文件和实时流共用的 FrameRedactor 按类别、一对一关联历史与当帧检测，防止车牌给人脸续期，以及同一检测重复取消相邻目标的遮挡。

连续检测采用保守边缘平滑：向外扩张立即覆盖当前框，向内收缩按源时间间隔渐进；单侧额外余量最多为当前框对应边长的25%。时间常数0.1秒是本轮合成序列和短片验证的初始值，并非所有场景的最终校准。平滑后的框包含当帧可信检测框，不用滞后位置替换当前检测。历史仍有128条上限；没有真实检测续期时仍受原有0.2/0.5秒寿命约束，转场/尺寸/时钟重置保持原规则。

局部补检按历史类别请求模型：人脸补检不再运行车牌推理，车牌补检不再运行人脸推理；全帧仍检测两类。任何实际执行的模型或局部补检异常仍向上传播，不能返回部分成功画面。没有新增依赖、模型、对外配置或API字段。

## 验证

- 新增时序回归先在旧实现复现框突然收缩和边缘抖动；后续测试另外复现了同一检测抑制两个重叠目标以及非法类别未拒绝。均已修复。
- `python -m pytest tests/unit tests/integration/test_video_pipeline.py -q`：209项通过，涵盖移动覆盖、有限拖尾、过期、类别隔离、局部失败传播、音轨和时间戳机制。
- GTX1080真实模型核对15个可用固定质量样例，标注遮挡/保留区域通过。`rtsp-green`截图缺失，未计为通过。
- 原视频1的1.8–2.5秒、视频2的9.8–10.5秒各15帧进入共用FrameRedactor；核对2秒小脸、10秒侧脸遮挡以及10秒手提包原像素。此为连续解码/遮挡验证，不是完整MP4编码、RTSP或逐帧人工质量认证。
- 同一局部裁剪交错运行全类别和仅人脸检测，排除首轮，后三轮中位耗时约267→201ms，减少约25%；人脸框和分数完全相同。仅为一个裁剪的局部补检收益，不是全片提速比例。

本地证据位于 `data/validation/optimization-20261021/`：源码基线、分段profile、`verify.py`、`quality-validation.json`、`recheck_benchmark.py`、`class-recheck-benchmark.json`。素材未上传。

## 尚未完成

当前每帧多模型与分块主路径仍在，不能达到或承诺两路15–30 FPS。之前CenterFace直接替换在困难侧脸上退化，未切换默认模型。后续需要比较轻量主检测和独立困难目标发现路径，并在实际RTX6000上验证两路吞吐、延迟、丢帧和画质。旧quality仍是质量对照。

本次平滑会增加有限的周边遮挡；若原检测是误检，平滑不能识别它的语义错误。多人交叉仍可能存在关联错误，未实现完整运动预测或身份跟踪，也未宣称全片误打码、漏遮或闪烁归零。尚未部署、未推送。

## 第二轮：重复轨迹与背景拖尾（opt-20261021-02）

第一轮部署后的完整视频1测得单路3.39 FPS，未达到目标。80秒附近的异常遮罩经本地真实模型复现：多模型/多视图重复框分别建立历史轨迹，小脸快速移动又超出原模板搜索窗口，含背景的模板会锁在旧位置，积累旧遮罩并反复触发局部推理。

本轮仅修改视频/流共用的时序处理：

- 同类别、IoU至少0.6的当帧框合并为包围矩形，保留所有原框边缘，避免重复建轨；不使用会丢弃较宽框的NMS。
- 模板使用框内中心60%区域，搜索范围扩到96像素，减少外扩背景干扰并允许小目标快速平移。
- 匹配后反向验证，要求回到原模板位置的误差不超过2像素，防止跳到重复纹理。
- 模型、检测阈值、逐帧全图检测、遮罩请求参数和历史过期规则不变。

回归新增快速小脸移动、重复模型框的完整覆盖与单轨迹、类别隔离、重复纹理拒绝。15个可用固定真实模型质量样例通过，另对视频1的1.8–2.5秒和视频2的9.8–10.5秒各15帧检查小脸/侧脸及保留区域；缺失的`rtsp-green`仍未验证。

## 第三轮：降低密集分块成本（opt-20261021-03）

按上述取舍，将quality内部补充检测的源分块边长从640提高到1920：最长边不超过1920的输入只做一次全图补充检测；3840×1080从17个视图降为4个。每个视图仍按默认最长边1280缩放到模型输入，覆盖全画面，不跳过图像区域。单独cpu后端仍使用原640分块。

完全取消4K分块的实验会漏掉image-7中约25–30像素的人脸，因此未采用。大分块方案保留该图片全部三个必须遮挡的标注内区。未增加极小目标的专用跟踪或补检逻辑，也未主动删除已检出的小目标；不保证20源像素以下目标的覆盖，这不是严格的尺寸过滤器或更大目标的召回保证。

四份模型、FP32、阈值、跨模型确认、原图扩框、逐帧检测、遮罩样式参数和编解码设置沿用第二轮。没有新增对外配置或依赖。

### 验证和取舍

14个可用且仍要求遮挡/保留的固定质量样例全部通过CUDA真实模型检查，包含4K多人、近处侧脸、五张夜间车轮误遮回归和同帧车牌；第15个样例为上述允许漏遮的极小脸，当前单帧未遮挡。`rtsp-green.png`仍缺失，未计为通过。

原先“2秒极小脸必须立即确认”的测试按用户新要求移除，标注转入`optional_masked_regions`，保留坐标及素材哈希；其他必须遮挡、必须保留区域不变。连续视频2的10秒近处侧脸及手提包原像素断言通过；单元测试新增1920输入单视图坐标映射、4K四视图边界覆盖和两种分块策略的极端尺寸覆盖检查。

执行单元、视频机制和可运行的CPU质量探针：244项通过、1项未执行（该集合扫描包含缺失的rtsp-green截图；14个可用样例另由本地脚本检查）。补齐两种分块策略的极端尺寸测试后，再执行单元和视频机制测试，238项通过（27.86秒）。显式`RUN_GPU_TESTS=1`的GPU探针3项通过，核对CUDA模型/实际算子、标注区域及串并行一致性。原始结果在`data/validation/optimization-round03/`的`assets.json`、`clips.json`和`clip-summary.json`。
