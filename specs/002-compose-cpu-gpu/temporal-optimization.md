# 视频时序遮挡与按类别补检

2026-10-21。目标仍为 RTX 6000 至少两路、每路15–30 FPS；本次完成第一阶段改动，不代表整体性能目标达成。

## 改动

三个检测后端增加内部 `detect_regions` 接口，在扩框后保留类别和置信度；原 `detect` 仍返回相同格式的坐标列表。图片处理契约不变。视频文件和实时流共用的 FrameRedactor 按类别、一对一关联历史与当帧检测，防止车牌给人脸续期，以及同一检测重复取消相邻目标的遮挡。

连续检测采用保守边缘平滑：向外扩张立即覆盖当前框，向内收缩按源时间间隔渐进；单侧额外余量最多为当前框对应边长的25%。时间常数0.1秒是本轮合成序列和短片验证的初始值，并非所有场景的最终校准。平滑后的框包含当帧可信检测框，不用滞后位置替换当前检测。历史仍有128条上限；没有真实检测续期时仍受原有0.2/0.5秒寿命约束，转场/尺寸/时钟重置保持原规则。

局部补检按历史类别请求模型：人脸补检不再运行车牌推理，车牌补检不再运行人脸推理；全帧仍检测两类。任何实际执行的模型或局部补检异常仍向上传播，不能返回部分成功画面。没有新增依赖、模型、对外配置或API字段。

## 验证

- 新增时序回归先在旧实现复现框突然收缩和边缘抖动；后续测试另外复现了同一检测抑制两个重叠目标以及非法类别未拒绝。均已修复。
- `python -m pytest tests/unit tests/integration/test_video_pipeline.py -q`：209项通过，涵盖移动覆盖、有限拖尾、过期、类别隔离、局部失败传播、音轨和时间戳机制。
- GTX1080真实模型核对15个可用固定质量样例，标注遮挡/保留区域通过。`rtsp-green`截图缺失，未计为通过。
- 原视频1的1.8–2.5秒、视频2的9.8–10.5秒各15帧进入共用FrameRedactor；核对2秒小脸、10秒侧脸遮挡以及10秒手提包原像素。此为连续解码/遮挡验证，不是完整MP4编码、RTSP或逐帧人工质量认证。
- 同一局部裁剪交错运行全类别和仅人脸检测，排除首轮，后三轮中位耗时约267→201ms，减少约25%；人脸框和分数完全相同。仅为一个裁剪的局部补检收益，不是全片提速比例。

## 尚未完成

当前每帧多模型与分块主路径仍在，不能达到或承诺两路15–30 FPS。之前CenterFace直接替换在困难侧脸上退化，未切换默认模型。后续需要比较轻量主检测和独立困难目标发现路径，并在实际RTX6000上验证两路吞吐、延迟、丢帧和画质。旧quality仍是质量对照。

## 第五轮：保留检测头的混合精度骨干（opt-20261021-05）

目标仍是RTX6000至少双路、每路15–30 FPS，同时控制误打码和闪烁；截至第四轮服务器单路6.26 FPS，未达标。第五轮先前的独立CUDA stream并行、线程数、JIT开关没有可靠收益，轻量候选级联漏掉三处必验人脸，因此均未采用，证据位于 `data/validation/optimization-round05/`。

本轮在计算能力主版本至少8的CUDA设备上，仅将两份EgoBlur卷积骨干转换为FP16；归一化、候选生成、ROIAlign、检测头及后处理保持FP32。骨干输出转回FP32后，按两份固定Gen1导出图各自的特征连接执行原检测头。源尺寸元数据留在CPU，32倍数补边与原图一致。CPU及较旧GPU维持原FP32路径，不增加依赖、配置、权重或接口参数。

四份权重、输入尺寸、逐帧检测、阈值、极小目标规则、跟踪和编解码不变。混合精度不是逐像素无损变换：分数与框会有浮点变化，可能影响临界目标，需真实素材回归；不能通过修改标注掩盖退化。适配仅针对当前固定Gen1导出图，更换模型导出版本须重新验证。

### 本地正确性与硬件限制

拆分FP32原型在侧脸样例上输出与原模型完全一致。半精度骨干原型的15张可用样例全部必验遮挡与保留区域通过，缺失rtsp-green未测；现有极小目标观察项不作为召回保证。真实代码新增GPU测试，强制执行混合精度而非在旧GPU跳过，核对两份骨干/候选生成/ROI头的精度、319×321非整齐尺寸、空画面、4K多人、近处侧脸和夜间车轮/车牌。6项GPU测试通过（26.89秒）。

本地GTX1080无Tensor Core，强制半精度的67帧连续片段更慢（FP32约23.46秒、混合精度约39.71秒），这也是禁止旧GPU默认启用的原因；各片段独立跟踪，近处侧脸及手提包断言通过。该数据不能预测RTX6000 Ada速度。必须在目标服务器部署后实际验收；若无可靠收益或效果回退，撤回此改动。

采样针对原始最长边大于检测工作尺寸的全图调用，在第64/424/768次各记录一次。局部复核不占用采样序号。每任务至多三份32 MiB trace，先写临时文件再原子发布；超预算删除本次临时文件并明确失败，不重跑模型。只为请求采样的CUDA视频挂接采样器，每个模型调用仍执行一次。

GET /v1/tasks/{id}/diagnostics返回collecting/complete/partial/failed和采样摘要；sample查询仅允许64/424/768，返回该任务当前attempt内的原始JSON。不存在任务404，未准备好409，非法索引422；解析后的文件路径必须留在任务目录内。采样器错误仍导致任务明确失败，诊断状态同步保留，不输出原始异常中的地址或凭据。

CPU注解范围确定主车牌调用的线程和起止，再按该范围内runtime/driver的correlation关联GPU活动，排除补模型线程及profiler清理同步。同步/分配和GPU活动采用区间并集，分别保留内核时间之和；不能把重叠内核和范围相加算总耗时。CPU算子表只统计同线程范围内的self时间。名称在摘要截断至256字符并标记，完整名字保留在原trace。仅涵盖主车牌图内部，不能以其HToD/DToH代替整个检测管线的传输量。

每份记录前一未采样全图调用的耗时、实际GPU名称、输入形状/设备/类型、参数精度、主要CUDA内核及CPU算子。profiling有明显扰动，GPU执行还可能晚于主机调用返回，不能以采样host/GPU时间比例推导正常独占占比；采样任务FPS不能当作性能提升或达标证据。必须保留普通双路对照。

最终344项默认检查通过（29.61秒）、30项条件跳过；41项真实GPU/媒体检查通过（101.16秒），18条上游警告。实际4K输入、强制半精度及真实并行检测后台线程的三个采样均有GPU内核，输出与未采样基线逐像素相同；未采样位置/局部调用不启动profiler，采样完整性、预算失败不重跑、私有任务传递、API和目录边界均有测试。将主线程归属条件反转后新测试明确失败，恢复后通过。之前API实现缺失时6项先失败。记录data/validation/device-profile-20261022/{api-before.log,mutation.log,unit-media-final.log,gpu-media-final.log,parallel-gpu.log,local-probe.log}。
