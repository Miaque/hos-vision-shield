# 已知视频问题修复与下一步优化

2026-10-20。范围：人脸视频1的2～3秒漏遮、人脸视频2的10秒侧脸漏遮及手提包误遮、文件输出体积。保留原模型、逐帧全图检测、分辨率和时间戳；不以抽帧换速度。

## 根因与修复

- 手提包：两路低置信度车牌框互相佐证。弱车牌现在必须得到另一模型高分全图确认，或通过原有局部复核。
- 小脸：部分候选在进入局部复核前被分数门槛丢弃。弱小脸允许进入局部确认，但须满足高分主模型确认，或主模型正向与镜像的匹配结果同时确认；弱侧脸须通过放大后的双模型定位确认。没有直接降低全局起框阈值。
- 运动漏检：旧逻辑在原位置保留200毫秒，既不跟随运动，也不能覆盖较长的短暂漏检。现在匹配相邻帧原始图像的局部纹理，匹配失败立即局部复核；只有真实检测能续期，单纯跟踪最长500毫秒。匹配、复核均失败时，旧框最多保留200毫秒。状态上限128个目标，场景/尺寸/时钟变化仍重置。
- 文件编码：显式使用 libx264 slow / CRF 23；源视频码率可用时设置115% maxrate及两秒bufsize。直播仍使用原低延迟配置。VBV不是文件大小硬上限，源片低码率或高运动时仍可能损失细节。

## 验证与证据

本机 GTX 1080 的真实模型校验不能代替服务器 RTX 6000 Ada 验收。

- 单元测试及视频管线：183项通过，覆盖运动补偿、真实检测续期、过期/场景重置、局部复核异常传播相关检测路径、编码选项及直播配置。
- 本地15个可用质量标注样例全部通过，包括新增的10秒侧脸、同帧手提包保留和视频1的2秒小脸。历史 `rtsp-green.png` 缺失，因此不宣称完整历史素材集通过。素材保存在Git忽略的 `samples/robot-quality/`，复现真实模型测试需保留原素材及manifest中对应哈希。
- 文件编码独立试验：将旧脱敏结果解码后按原片码率预算重新编码，2450帧、时间戳不变，56,466,690字节降至42,782,676字节，原片41,582,748字节。**此结果仅验证编码，不是修复检测后的完整视频结果。**
- 对8～12秒与87～91秒共160帧的相同旧脱敏图像比较，选定编码参数的VMAF均值98.19、最低90.48；参考是编码前脱敏帧，不是原始未遮挡画面，不能据此宣称无损。该指标也不评估脱敏正确性。
- 连续片段输出与检查记录保存在 `data/validation/known-issues-20261020/`。局部人工检查和已标注区域测试不等于全片零漏遮认证。

## 优化顺序

修复增加局部确认开销，本轮不宣称吞吐提高。上一次服务器旧版本测试为2450帧/661.20秒，约3.71fps；任务期间设备GPU平均利用率约13.1%。这些数据说明仍有空闲，不足以直接确定唯一瓶颈。

1. 在服务器按同一视频、单任务、固定版本测量解码、GPU主检测、CPU补充检测、局部复核、跟踪、编码耗时和调用次数。将资源采样关联任务ID，区分加载/处理/收尾；先确认新增局部复核的成本。
2. 优先减少重复局部复核：同帧重叠候选复用同一次结果，保持候选覆盖、阈值和输出语义。使用固定样例与连续帧对比，确认收益后再合并。
3. 按后续明确要求，已将补充检测迁到GPU，见[四模型CUDA推理](cuda-detail.md)。服务器部署后再判断是否需要分块批处理；保持FP32核对预处理、框坐标与标注区域。FP16不是默认无损替换。
4. 仅当编码占比显著时比较NVENC与现有x264：同时考核耗时、体积、非遮挡区域画质。不能只因GPU空闲就更换编码器。

每步都保留已知漏遮/误遮回归门槛，不承诺未经实测的倍数或实时帧率。当前未部署本轮修复；服务器全片效果、吞吐、真实RTSP及并发负载仍需验收。
