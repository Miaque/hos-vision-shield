# 首版验收记录

2026-10-18。代码及本机部署已交付；T040人工检测质量复核仍未完成，因此不把整个规格标记为全部验收通过。

## 可复现检查

配置TEST_REDIS_SERVER指向本机Redis7.4.3后执行 `uv run pytest -q -x`：**69 passed，2 warnings，385.20秒，无跳过**。
警告来自官方TorchScript权重的加载弃用与meshgrid旧用法，未屏蔽；当前固定版本真实运行通过。
随后补充接口类型、Swagger上传描述、停止/重启竞争与损坏视频边界，针对性回归40项通过（236.90秒），记录在data/validation/final-regression.log。最终又补充3GP容器及逐帧尺寸上限验证，视频/流流水线10项通过（1.73秒）；这些用例与全量存在重叠，不相加作总数。
测试均使用临时端口、临时Redis和受控媒体源，没有清空本机已有数据库。测试结束回收自身进程，原始/结果文件按要求保留。

机器人补充后的当前1280检测/16秒音频缓存配置，全量回归**82 passed，2 warnings，472.57秒，无跳过**，包括1728×536带AAC的RTSP恢复；素材对照、实际漏检/误检与CPU代价见robot-media.md。69项为历史基线，不与当前用例相加。人工质量验收仍未通过。

本机启动指南已实际执行：基础服务-Check通过健康/AOF always/noeviction；应用-Check -StreamWorkers 2通过API、文件池、流池及MediaMTX检查。退出只回收自身进程树。
使用方式见根README及quickstart.md；模型来源/固定版本/哈希见models/manifest.json。

## 设计校准与剩余范围

按用户要求使用Windows本地进程，移除Docker/WSL2前提。官方模型已由代理下载并校验，未要求用户自行寻找权重。
640基线约1.7秒/帧的小尺寸双模型CPU推理加RTSP积压超出最初2秒AAC缓存，曾校准为4秒；机器人1280检测进一步变慢，当前为16秒，仍有4MiB硬上限，超限重建而不无限缓存。
输入容器保持到输出结束；关闭JIT冷帧优化开销；当前检测最长边1280并扩框、在短时源时间内补遮挡；机器人补充证据和当前回归见robot-media.md。原性能表只代表640历史基线。
模块方向为api→jobs/media，检测与遮挡不依赖Web；关键进程所有权、时钟、缓存与CAS处有必要注释。未增加用户系统、删除、模型插件或GPU调度。
没有配置.specify/extensions.yml，前/后置hooks均跳过。没有自动提交Git，保留既有.agents/.vscode等内容。

真实摄像头、长时间音画漂移、多路满载、TLS证书/代理组合及人工检测质量尚未验收。API启动自检不等于服务持续运行；按README在两个终端分别启动基础服务和应用。
