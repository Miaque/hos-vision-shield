# Feature Specification: 图片、视频与视频流人脸车牌脱敏

**主干分支**: `main`

**Created**: 2026-10-18

**Status**: 图片、视频和 RTSP 链路已实现；完成范围与未完成验收见[任务清单](tasks.md)和[验证记录](validation/gates.md)。后续 CPU/GPU 部署见[部署规格](../002-compose-cpu-gpu/spec.md)。

**Input**: User description: "使用 Python、FastAPI，通过 RESTful API 对图片、视频和视频流中的人脸、车牌脱敏；使用 Taskiq 队列，流处理放在 worker 中并可扩展。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 提交图片并获取脱敏结果 (Priority: P1)

内部调用方上传图片或提供远程图片地址，获得任务编号，查询状态并下载结果对照验证。

**Why this priority**: 建立可独立验证的检测、遮挡及任务交付流程。

**Independent Test**: 分别上传和通过远程地址提交含有人脸与车牌的图片，查询任务并检查结果。

**Acceptance Scenarios**:

1. **Given** 有效图片且容量可用，**When** 提交，**Then** 返回任务编号，完成后可查询成功状态并下载结果。
2. **Given** 检测到人脸与车牌，**When** 处理成功，**Then** 两类区域均被实心色块覆盖。
3. **Given** 有效且未检测到目标的图片，**When** 处理完成，**Then** 返回有效图片，不宣称绝无漏检。
4. **Given** 无效图片或下载失败，**When** 处理请求，**Then** 明确拒绝或标记失败，不返回伪装为成功结果的原始图片。

---

### User Story 2 - 获取完整脱敏视频文件 (Priority: P2)

内部调用方上传视频或提供远程文件地址，查询任务状态，完成后下载结果。
原始文件和结果保留用于人工对照，音频原样保留。

**Why this priority**: 提供可回看、可对照的有限时长媒体脱敏结果。

**Independent Test**: 提交含移动人脸、车牌及音频的视频，检查输出、音频、失败与取消路径。

**Acceptance Scenarios**:

1. **Given** 有效视频，**When** 提交，**Then** 无需等待整个视频处理完成即可获得任务编号。
2. **Given** 含目标和音频的视频，**When** 处理完成，**Then** 保持画面顺序、时长与音频，每个输出画面均经过脱敏处理。
3. **Given** 处理速度低于播放速度，**When** 持续处理，**Then** 延长完成时间，不主动丢帧赶进度。
4. **Given** 视频处理失败或被取消，**When** 查询或下载，**Then** 区分失败与取消，未完成产物不能作为成功结果下载。

---

### User Story 3 - 播放脱敏流并恢复故障 (Priority: P2)

调用方创建持续流任务，将播放地址交给其他系统；断流或处理进程重启后自动恢复，明确停止后不再恢复。

**Why this priority**: 满足实时摄像头接入，并支持增加处理资源承载更多独立视频流。

**Independent Test**: 接入测试流并播放输出，模拟断流、进程重启与主动停止，核对状态及输出。

**Acceptance Scenarios**:

1. **Given** 可访问的源流，**When** 创建任务，**Then** 获得任务编号与播放地址；状态明确区分准备中与输出就绪。
2. **Given** 处理速度跟不上输入，**When** 缓冲达到上限，**Then** 丢弃未处理的旧帧，不透传未经脱敏的帧。
3. **Given** 输入中断或进程退出，**When** 来源或处理资源恢复，**Then** 未停止任务自动恢复，同一任务无多个有效输出生产者。
4. **Given** 运行或恢复中的任务，**When** 主动停止，**Then** 释放活动资源，后续重连与进程重启不会重新启动该任务。
5. **Given** 多个独立流任务及足够资源，**When** 增加处理进程，**Then** 可承接更多任务，调用方式不变。

### Cross-cutting Acceptance Scenarios

1. **Given** JPEG、PNG、MP4/H.264/AAC 及无音轨视频样本，**When** 分别提交，**Then** 正常处理并保留对应输出格式；不支持的格式明确拒绝或失败，不静默删除音轨。
2. **Given** 内部网络可达且未提供身份凭据，**When** 提交、查询、下载或停止任务，**Then** 操作不要求登录或权限校验；任意路径与未授权远程目标仍被拒绝。
3. **Given** 文件任务结束，**When** 检查任务关联产物，**Then** 原始文件和生成结果仍保留，无自动过期删除；流任务不产生额外录像。
4. **Given** 工作容量已满或处理被取消，**When** 提交或操作任务，**Then** 明确反馈容量或取消状态，查询和停止操作仍可完成，活动资源按生命周期释放。
5. **Given** 多个任务及含凭据的源地址，**When** 获取结果与检查日志，**Then** 结果按任务对应，无原始媒体或访问凭据泄露到日志。

### Edge Cases

- 无目标、多目标、重叠、出画、遮挡和小目标；无检测结果不能证明不存在漏检。
- 损坏媒体、扩展名伪装、下载中断、远程地址失效或重定向到未授权目标。
- 队列已满、磁盘不足、模型不可用：明确拒绝或失败，不以原始媒体代替脱敏结果。
- 流反复断开、输出端不可用、进程失联、重复投递，以及主动停止与自动恢复竞争。
- 无音轨、方向信息、尺寸变化和不支持的编码；输出不得静默丢失音频或错误旋转。
- 文件持续保留造成存储增长；不得覆盖其他任务的文件或静默损坏产物。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 图片与视频文件支持上传及远程 HTTP/HTTPS URL，不接受调用方指定的服务器本地路径。
- **FR-002**: 所有媒体处理请求通过任务队列执行并返回可查询的任务编号；接收成功不等于处理成功。
- **FR-003**: 每个任务同时处理人脸与车牌，以实心色块遮挡，不提供单类目标选择。
- **FR-004**: 不做身份识别、车牌文字识别及音频脱敏；保留视频与流的原有音频。
- **FR-005**: 文件任务支持查询、成功结果下载与取消，区分等待、处理中、成功、失败和已取消。
- **FR-006**: 视频文件完整处理，不因负载主动丢帧，保持顺序与时间关系。
- **FR-007**: 视频流首版支持 RTSP 输入和 RTSP 输出，通过任务接口返回播放地址。
- **FR-008**: 流任务区分等待、连接中、运行中、恢复中、已停止及失败，明确输出是否就绪及故障原因。
- **FR-009**: 流中断自动重连；处理进程重启后，未停止的流任务自动恢复，明确停止的任务不得恢复。
- **FR-010**: 重复投递及故障恢复不得造成同一任务存在多个有效输出生产者；停止请求必须阻止后续自动恢复。
- **FR-011**: 实时流限制缓冲并允许丢弃未处理的旧帧；输出帧必须经过脱敏，故障不得回退为原始画面。
- **FR-012**: 支持增加处理进程承接更多流任务，不改变调用方提交、查询和停止方式。
- **FR-013**: 首版保留已接收的原始文件与生成结果用于验证；不自动删除，不提供删除功能，视频流不额外录像。
- **FR-014**: 文件必须能按任务对应；未完成产物不能冒充成功结果，接口不得暴露任意服务器文件。
- **FR-015**: 首版内部部署，不实现登录、API Key、角色或任务归属权限管理，由部署方限制网络可达范围。
- **FR-016**: 必须校验媒体格式、大小等资源限制和远程访问目标；允许授权的内网摄像头，禁止任意内部地址探测。
- **FR-017**: 处理不得阻塞其他任务的提交、查询和停止；并发与队列有上限，容量不足必须明确反馈。
- **FR-018**: 超时、取消、失败与停止释放活动连接和处理资源；FR-013 明确保留的文件不属于自动清理范围。
- **FR-019**: 日志可按任务定位问题，不记录原始媒体内容、源流凭据及含凭据的完整地址。
- **FR-020**: 首版支持 JPEG/PNG 图片、MP4 文件及 H.264 视频编码，文件与 RTSP 流支持 AAC 音频或无音轨；输出图片保持输入格式，视频文件输出 MP4/H.264，流输出 RTSP/H.264，已有 AAC 音频原样保留。不支持 H.265 等其他编码，必须明确拒绝或失败。

### Key Entities *(include if feature involves data)*

- **媒体输入**：上传文件、远程文件地址或源流地址，关联媒体类型、任务与校验结果。
- **文件脱敏任务**：有限处理过程，包含任务编号、状态、输入、结果及失败原因。
- **流脱敏任务**：持续处理过程，包含任务编号、期望运行状态、实际状态、源流及播放地址。
- **脱敏结果**：成功生成的图片、视频文件或运行中的输出流，与原始输入明确区分。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 兼容格式的正常验收样本分别通过上传与远程地址提交后，100% 可查询终态并获取可打开的结果。
- **SC-002**: 单独验证遮挡步骤时，100% 已提供的有效目标区域被实心色块覆盖；模型漏检与误检另行评估，不能用该指标代替。
- **SC-003**: 文件视频验收不因负载主动丢帧；有音轨、无音轨样本均可正确播放，原音频不修改。
- **SC-004**: 断流、进程重启、停止与恢复竞争三个故障场景各重复 3 次，均无重复有效输出；明确停止的任务均不重启。
- **SC-005**: 过载测试中缓冲和活动处理数不超过声明上限，未经处理的输出帧数量为 0。
- **SC-006**: 首版交付一份可复现的性能实测报告，覆盖图片、视频文件及持续流，记录硬件、样本、分辨率、输入帧率、并发数、处理耗时或速度、流端到端延迟、丢帧数及资源占用；负载期间记录任务查询和停止的完成时间。各适用测量项必须有结果，不承诺固定并发路数或延迟门槛。
- **SC-007**: 首版对一组固定、可追溯的代表性图片和视频画面进行人工复核，样本覆盖人脸、车牌、两者共存、无目标及遮挡或小目标；记录各类目标总数、漏检数、误检数和复核画面范围，并保留原始与脱敏结果供对照。未复核范围不得计入准确率结论；首版不设生产准确率门槛。

## Assumptions

- 已确认技术约束：Python、FastAPI、RESTful API、Taskiq，流在 worker 中处理；这里只保留用户选择，不展开设计。
- 遵循宪章的异步非阻塞、模块职责、必要注释与验证约束。
- 首版供内部系统调用，不建设管理页面、多租户系统或识别结果服务。
- 媒体服务部署、队列后端、持久化方式、模型选择及工作进程组织在规划阶段确定。
- 文件清理属于明确后续事项；首版不设自动过期时间，需部署方监测可用空间。
- 原音频未脱敏，输出不等于音视频整体匿名化；模型不能宣称绝无漏检。
- 文件任务崩溃后自动续跑、跨重启断点续传与历史流录像不作为本轮已确认能力。
- 性能和检测效果首版以实测报告为验收交付物；样本清单、测试硬件及运行参数在执行验证前固定，报告不代表未测试环境的容量或准确率保证。

### 2026-10-18 补充：巡逻机器人移动拍摄

- 图片、视频和流来自带摄像头的巡逻机器人，包含超宽画面、运动模糊、夜间眩光、抖动及远处小目标；用户提供本机demo目录作为固定对照样本。
- 调整检测细节保留、检测框边缘遮挡及短时漏检补偿，明确额外遮挡与计算耗时的代价；不以模糊或未检出作为不存在隐私目标的证明。
- 短时补偿必须受源时间戳和帧尺寸约束，跳帧、转向/场景明显变化或会话重建后不能长期沿用旧位置。不能保证未曾检出的目标得到遮挡。
- 效果报告区分自动框计数、代理逐样本观察与人工标注验收；不得从未经标注画面计算召回率。原始素材不覆盖、不上传到外部服务。

### 2026-10-18 补充：开发环境CPU优化

- 用户明确本轮仅使用CPU，优化现有检测速度与遮挡效果；不安装CUDA、不以GPU作为运行条件。
- 可以替换本机检测实现，保留人脸和车牌同时检测、无识别及异步媒体子进程边界；REST接口不变，保留原模型供对照。
- 固定机器人素材比较同帧遮挡与耗时，并复测真实RTSP；报告误遮、漏检和丢帧，不以提速或框数增加宣称质量验收通过。

### 2026-10-18 补充：效果优先

- 用户确认效果优先，上一轮CPU方案复核存在远处车牌漏遮和大范围误遮，要求继续优化；本机CPU允许变慢，不以速度优先替代脱敏覆盖要求。
- 使用现有检测模型互补，保留原方案供对照；对已确认目标及误遮区域建立带源哈希的小范围回归，区分固定样本改善与完整质量验收。
- 本阶段仅覆盖 CPU 效果优化；后续本机 CUDA 与服务器单卡部署见[部署规格](../002-compose-cpu-gpu/spec.md)。
