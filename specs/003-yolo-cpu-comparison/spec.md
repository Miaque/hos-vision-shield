# Feature Specification: YOLO 人脸与车牌脱敏 CPU 效果对比

**Feature Branch**: `feature/yolo-comparison`

**Created**: 2026-10-19

**Status**: Ready for planning

**Input**: User description: "在新的 worktree 上开发 YOLO 版本，和 main 主干的 CPU 版本做效果对比，使用 C:\Users\zhanjh\Downloads\demo 数据集验证。先只在 CPU 上对比，先看效果；其他按照推荐。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用候选版本完成相同的脱敏任务 (Priority: P1)

作为现有调用方，我希望候选版本继续对图片、视频文件和持续视频流中的人脸、车牌进行实心遮挡，不改变提交、获取结果和停止任务的使用方式。

**Why this priority**: 比较对象必须提供相同的脱敏能力，检测效果才具有业务意义。

**Independent Test**: 分别验证含人脸、含车牌、两者同时存在及无目标的媒体，核对任务的成功、失败与停止行为。

**Acceptance Scenarios**:

1. **Given** 图片或视频含可辨认的人脸和车牌，**When** 候选版本完成处理，**Then** 对检测到的对应区域施加与现有版本一致的实心遮挡，并提供可查看或播放的结果。
2. **Given** 输入不含两类目标，**When** 完成处理，**Then** 不应凭空遮挡其他物体；实际误遮挡必须在评估中记录。
3. **Given** 已有调用方提交文件或流任务，**When** 使用候选版本，**Then** 提交、状态查询、结果获取及停止方式与主干兼容；流停止后不再自动恢复。
4. **Given** 模型不可用、媒体损坏或处理被取消，**When** 无法正常完成，**Then** 明确报告失败或取消，释放资源，不把原始未处理媒体作为成功结果返回。

---

### User Story 2 - 查看同一批素材的公平效果对比 (Priority: P1)

作为评估者，我希望在同一台机器上仅使用 CPU，查看主干与 YOLO 对同一份 demo 素材的结果，优先判断漏遮挡是否减少，同时看清误遮挡代价。

**Why this priority**: 本轮核心是效果，硬件加速不能混入模型效果结论。

**Independent Test**: 对冻结的 21 份素材生成两组结果，对照原图或同一视频时刻查看输出，核对完整性和差异索引。

**Acceptance Scenarios**:

1. **Given** 固定的 16 张图片与 5 段原始视频，**When** 执行两组处理，**Then** 两组均处理全部图片及全部视频时长，不以视频前三帧或短片段冒充完整结果。
2. **Given** 已生成两组结果，**When** 打开本地报告，**Then** 能按素材查看原始画面、基线结果和候选结果，视频差异定位到同一帧或时间点。
3. **Given** 任一素材失败或只完成一部分，**When** 汇总结果，**Then** 明确标为失败或未完成，不排除失败项后宣称全量通过。
4. **Given** 候选漏遮挡减少但误遮挡增多，**When** 报告结论，**Then** 分别展示两项变化及具体画面，不仅以速度或单一总分宣布胜出。

---

### User Story 3 - 获取有证据边界的可复核结论 (Priority: P2)

作为维护者，我希望获得人脸、车牌分别统计的质量结果及逐素材耗时，能够复核差异并决定是否值得进一步采用候选版本。

**Why this priority**: 把直观观感变成可追溯证据，避免把局部标注当作全量真值。

**Independent Test**: 使用冻结的清单和人工复核记录重新汇总，核对分类统计、分母、耗时与差异来源。

**Acceptance Scenarios**:

1. **Given** 全部图片和固定的视频抽样帧已标注，**When** 进行复核，**Then** 每个样本分别记录两类目标总数、完整遮挡数、部分漏遮挡数、完全漏遮挡数和误遮挡区域数。
2. **Given** 标注未经人工确认或目标无法判定，**When** 输出统计，**Then** 列出复核状态与争议项；未确认结果只能标为暂定，不宣称正式准确率。
3. **Given** 两组完成测量，**When** 查看耗时，**Then** 能看到每份素材处理时间、初始化时间与计时范围，不能把批处理时间表述为业务请求端到端时间。
4. **Given** 候选效果没有改善或证据不足，**When** 完成报告，**Then** 如实给出无改善、存在取舍或无法判断的结论，不以证明 YOLO 更好作为交付条件。

### Edge Cases

- 远处、模糊、侧脸、部分遮挡或画面边缘的目标：列出可判定目标和无法判定区域，不默认为无目标。
- 同一画面多个目标或视频中目标出现、消失：按图片或样本帧内的目标计数，不当作唯一人员或车辆数。
- 狗、衣物、路面、文字等非目标被遮挡：计入误遮挡；正确目标周围遮挡过大的情况另列案例。
- 某类没有真实目标或没有输出遮挡：零分母指标标为不可计算，不以 0% 或 100% 替代。
- 视频变帧率、时间戳偏移或解码失败：核对时序及完整性，不能比较不同时间的画面。
- 耗时过长或中途终止：保留已完成证据与未完成清单，不擅自缩短视频范围。
- 运行后修改模型、阈值或素材：保留新的独立记录，不覆盖原结果或只保留更好的样例。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 在独立 worktree 的 `feature/yolo-comparison` 分支开发候选版本；基线固定为 main 提交 `0664be4ae9edb6d0eac7bb2635d5563dad9d7956` 的默认 quality 组合在 CPU 上运行，不是名称为 cpu 的轻量方案，也不是单独 EgoBlur。
- **FR-002**: 候选的人脸和车牌检测均采用预训练 YOLO 模型。本轮不训练或微调，不增加其他检测类别、身份识别或车牌文字识别。
- **FR-003**: 两组仅在同一台机器的 CPU 上运行，记录实际环境；本轮不执行 GPU 比较或推断 GPU 表现。
- **FR-004**: 保持现有图片、视频、视频流的对外使用方式、实心遮挡方式、音频保留语义与失败保护；仅改变目标检测能力及本次必要的比较能力。
- **FR-005**: 使用 `C:\Users\zhanjh\Downloads\demo` 中现有 16 张图片、5 段视频，冻结文件清单和内容指纹。原始素材只读，结果另存本地，不上传或提交原始媒体。
- **FR-006**: 两组处理同一批全部原始媒体。视频完整处理与质量抽样统计分别说明；核对输出可读性、尺寸、帧数和时间对应关系，不静默抽帧或截短后报成功。
- **FR-007**: 在查看两组结果前固定全部图片与视频抽样帧清单、标注和计数规则。视频样本覆盖每段视频的起始、中间、结束部分；具体密度在评估设计中确定并冻结，不能按哪组效果好来挑帧。
- **FR-008**: 标注覆盖选中样本内所有可判定的人脸与车牌，记录人工复核状态及不确定区域。既有局部回归标注不能冒充完整标注，模型或代理生成的标注不能自动视为人工真值。
- **FR-009**: 分人脸、车牌报告完整遮挡、部分漏遮挡、完全漏遮挡与误遮挡数量。漏遮挡率为部分及完全漏遮挡目标数之和除以可判定目标总数。误遮挡区域指与两类真实目标均不对应的遮挡；正确目标周围遮挡过大的情况另列案例。分别报告图片与视频抽样统计、分母及不确定项。
- **FR-010**: 漏遮挡以应遮挡的可见敏感区域是否完整覆盖为依据，检测到了但遮挡不完整仍计入漏遮挡。报告展示判断规则和可回查画面，不能只凭检测框数量评价效果。
- **FR-011**: 两组保持相同源素材、公共输入尺寸策略、扩框与遮挡规则及处理资源配额。各模型必需的预处理和阈值允许不同，但须事先固定并记录；调整条件时保留新的运行记录。
- **FR-012**: 生成可本地查看的逐素材对比报告与可重新汇总的记录，包含源码版本、模型来源及版本、模型指纹、运行设置、素材指纹、失败项与复核状态。
- **FR-013**: 记录逐素材处理耗时与初始化耗时，说明是否包含解码、检测、遮挡和编码以及测量次数。本轮不设速度提升或实时处理门槛。
- **FR-014**: 结论先比较两类目标的漏遮挡，再说明误遮挡及遮挡范围代价，最后报告耗时。允许无改善、存在取舍或证据不足，不预设采用或合并候选版本。
- **FR-015**: 验证本次变更涉及的正确遮挡、无目标、无效媒体、检测失败和取消行为，保持现有资源限制。逻辑测试、真实文件评估与真实视频流验证分别报告，demo 文件测试不能证明真实流已验收。

### Key Entities *(include if feature involves data)*

- **基线版本 / 候选版本**：固定的现有脱敏方案与待比较方案，各自关联版本、模型及运行条件。
- **评估素材**：原始图片或视频，具备内容指纹、媒体信息及两组处理结果。
- **质量样本**：选定进行人工复核的图片或视频帧，关联原素材、帧位置、目标与争议区域及复核状态。
- **对比记录**：两组在同一样本上的遮挡判断、耗时或失败信息，可追溯到对应画面。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 固定的 21 份素材均有两组完整、可查看或播放的输出，共 42 份；失败或未完成时，该条件不算通过，并逐项列明原因。
- **SC-002**: 全部 16 张图片及冻结清单内 100% 的视频样本具备复核记录。正式质量结论仅使用已经人工确认的样本，其他样本及其占比单列。
- **SC-003**: 两组均提供人脸、车牌的完整遮挡、部分漏遮挡、完全漏遮挡、误遮挡数量与适用分母；100% 的差异记录可定位到原素材及对应画面。
- **SC-004**: 21 份素材分别具有两组耗时或明确失败记录，初始化时间单列，注明计时范围与测量次数。
- **SC-005**: 既有调用方无需修改提交、查询、获取结果与停止操作即可使用候选版本；相关正常、失败及取消行为验证全部通过。
- **SC-006**: 形成明确的比较结论，分别说明人脸、车牌的改善、持平、退化或证据不足，列出全部已确认的候选新增漏遮挡样例；不以性能提升抵消未披露的质量退化。

## Assumptions

- 用户于 2026-10-19 确认：同时替换人脸与车牌检测，使用预训练模型，首轮不训练；只在 CPU 上比较；减少漏遮挡优先，同时报告误遮挡和耗时，允许 YOLO 没有更好。
- 本轮目标是可靠的比较证据，不承诺零漏遮挡，不预设改善百分比，也不自动合并 main。
- 预训练模型须可取得、覆盖对应目标且允许预期使用；具体模型及适配方案由设计阶段核实。
- 视频完整处理用于结果交付，人工标注仅覆盖固定抽样帧。抽样结果不外推为整段视频、其他数据集或真实视频流准确率。
- 采样密度、遮挡判断细则和运行配置须在首次正式比较前记录。对 demo 调参后的结果属于该数据集内比较，不宣称独立泛化验证。
- 保留原始音频，不扩大为音频脱敏。真实外部视频流、生产部署、并发压力与 GPU 表现不属于本次 demo 对比验收；保留流能力所需的回归验证仍在范围内。
- 大型产物保存在本地忽略目录，版本控制保留可复现的评估规则与摘要。主工作区已有未提交改动不属于本特性。
